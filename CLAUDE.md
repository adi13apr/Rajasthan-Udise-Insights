## Hard constraints
- **Never modify, unzip in place, or move `data/raw/`.** Raw zips are the source of truth.
- **Data-sharing terms of the UDISE+ portal:** data must not be redistributed, the
  source must be acknowledged ("Source: UDISE+, Ministry of Education, Government of
  India"), and no re-identification of schools. Therefore:
  - never commit raw data, bronze/silver/school-level data, or the DuckDB file;
  - CI and tests use **synthetic sample data** only (generated by a script);
  - publishing district-level aggregates and findings is fine.
- One command must run the whole pipeline end to end: `python run_pipeline.py`
  (and `python run_pipeline.py --sample` for the synthetic sample).

## Data facts (verified, do not re-derive)
- Source: UDISE+ Data Sharing Portal (microdata.udiseplus.gov.in), school-level CSVs
  inside zips, years **2024-25** and **2025-26**, all **41 districts** of Rajasthan.
- Files in `data/raw/<year>/`, names like `facility_data_RAJASTHAN_2024-25.zip`:
  - `profile_data_1`, `facility_data`, `teacher_data`: one **state-wide** file per year
    (district "All" on the portal, so the file name says RAJASTHAN).
  - `enrolment_data_1`: **one file per district** (the state-level file is not
    available on the portal; it returns "File Not Found").
  - Kota files (`*_KOTA_*`) also exist from early testing, so Kota schools appear
    twice for profile/facility/teacher. Duplicates must be handled (quarantined with
    a reason, never silently dropped).
- Key: `pseudocode` (school code), stable across years. Grain of profile/facility/
  teacher files = one row per school per year.
- Enrolment_1: one row per school per `item_group`/`item_id`; columns `cpp_b/g/t`
  (pre-primary) and `c1_b ... c12_t`. **item_group 1 (General/SC/ST/OBC) is a
  complete split**: sum it for totals. Transgender (`*_t`) columns exist only
  from 2025-26. item_group 4 = disability types; item_id 21 is undocumented.
- Schemas: `docs/DSP_Schema_2024-25.pdf`, `docs/DSP_Schema_2025-26.pdf`.
- Yes/No columns: 1 = Yes, 2 = No, **9 = not applicable** (treat as missing, never No).
- `rural_urban`: 1 = Rural, 2 = Urban (checked against village/urban-body names).
- `electricity_availability`: 1 = Yes, 2 = No, 3 = Yes but not functional.
- `total_class_rooms` is 0 for all but 6 schools in 2024-25. Rebuild classrooms as
  good + minor repair + major repair (matches exactly where the field is filled in).
- Undocumented codes found by profiling (DATA_QUALITY_LOG #23-27): `solar_panel` and
  `rain_water_harvesting` use 3; `anganwadi_yn` uses 0 (2024-25); `spl_educator_yn` uses 9.
- Management codes (column `managment`, spelled like this in the data): grouping in
  `reference/management_codes.json`, **validated against official totals** (codes 94, 95, 101 are
  government; with them, government teachers match the official 4,45,073 exactly).
  97 and 98 are non-government. Exact names still to confirm with the UDISE+ DCF.
- District spellings differ by year: BALOTARA/BALOTRA, CHITTAURGARH/CHITTORGARH,
  DHAULPUR/DHOLPUR, JALOR/JALORE, PRATAPGARH (RAJ.)/PRATAPGARH, mapped by
  `DISTRICT_ALIASES` in `config.py`.
- **Boundary change:** 189 schools changed district between years, 180 of them from
  ALWAR to KOTPUTLI-BEHROR. Model this explicitly (see PLAN, dim_school).
- In 2025-26, 114 central-government schools (codes 92, 93) have block
  "JAIPUR REGION" instead of a real block.
- Playground availability dropped by more than 5 points in 24 of 41 districts in one
  year: a reporting change. It is excluded from the infrastructure index and trends.
- **Official 2024-25 totals** (UDISE+ 2024-25 report and Parliament answers), all
  matched exactly by the current pipeline: schools 1,06,302; teachers 7,92,265;
  enrolment incl. pre-primary 1,63,64,187; single-teacher schools 6,117;
  zero-enrolment schools 215 (counting pre-primary); government schools 70,155,
  enrolment 77,82,390 (incl. pre-primary), teachers 4,45,073. Stored in
  `OFFICIAL` in `config.py`.

## Current code (as of the hand-off)
- `run_pipeline.py`: entry point.
- `pipeline/config.py`: paths and code mappings; loads `reference/*.json` (districts and
  aliases, management codes, official totals) under the same names as before.
- `reference/schema_columns.json`: every column of every dataset and year with type and
  documented codes, parsed from the schema PDFs by `scripts/extract_schema.py` (pdfplumber).
- `pipeline/ingest.py`: finds zips, reads CSV inside each zip in place, parses
  dataset/district/year from the file name. `load_all()` (stack + drop duplicates) is no
  longer used by the pipeline since P3: duplicates are quarantined in silver.
- `pipeline/bronze.py` (P1): each raw zip -> `data/bronze/<dataset>/year=<YYYY-YY>/
  <stem>.parquet`, all values as text, plus `_source_file`, `_source_row`,
  `_district_file`, `_year`, `_ingested_at`, `_run_id`. Incremental: SHA-256 per zip in
  `data/bronze/_state.json`; unchanged zips are skipped (`--full-refresh` to reload).
  Keeps duplicates. `build.py` still reads the raw zips until silver exists (P3).
- `pipeline/profiling.py` (P2): per column and year: dtype, null %, distinct, min/max,
  top values, invalid codes vs the reference JSON; duplicates on the natural key; schema
  vs data; year-to-year reporting changes. `reports/profiling/<layer>__<table>.csv` +
  `README.md` (problems only). School codes are never written to reports.
- `reports/run_manifest.json`: per-run record (files, checksums, rows, timings).
- `tests/`: pytest on synthetic zips built in a temp folder.
- `pipeline/silver.py` (P3): bronze -> typed, standardised tables in `data/silver/<table>/
  year=<Y>/` (`schools`, `enrolment` = item_group 1, `enrolment_other`, `facilities`,
  `teachers`). The cleaning functions moved here from `build.py` (district aliasing,
  yes/no mapping, classroom rebuild, management grouping, facility indicators). Checks
  bronze rows = silver + quarantine on every run. Rebuilt in full each run.
- `pipeline/rules.py` (P3): rules as data; errors -> `data/quarantine/<table>.parquet`
  (`_rule`, `_reason`, `_run_id`), warnings -> `flag_<rule>` columns.
  `docs/quality_rules.md` is generated from it (`python -m pipeline.rules`).
- `pipeline/gold.py` + `sql/` (P4): DuckDB star schema in `data/gold/udise.duckdb`, built by
  numbered SQL files from temp views `src_<silver table>` and `ref_*` tables. dim_year,
  dim_district (41), dim_management (key 0 = unmapped), dim_grade, dim_gender,
  dim_social_category, dim_school (SCD2 on district/block/management/rural-urban/category/
  type; 1,708 schools have 2 versions, 189 changed district), fact_enrolment (zero rows
  omitted), fact_teachers, fact_school_facilities (one row per school-year). `sql/tests/`
  checks (RI, grain, SCD2, totals) must all return 0 or the old database is kept.
  Exported to `data/gold/parquet/`.
- Marts (P5): `sql/10_int_school_year.sql` (school-year intermediate, never exported) and
  `sql/11_marts_district.sql` (`mart_district_year`, `mart_district_year_management`, one
  GROUPING SETS query). Exported to `data/gold/exports/*.csv` (committed). They replace the
  pandas `summarise()` (kept only as the test reference); old outputs frozen in `tests/regression/`.
- `pipeline/validation.py` + `sql/validation/` (P6): official indicators from gold vs
  `reference/official_totals.json` -> `reports/validation.md/.csv`. 8/8 exact for 2024-25.
- `scripts/benchmark.py` (P7): Kota enrolment by grade x gender 2025-26 on raw CSV (extracted
  to data/tmp), bronze (with/without partition filter) and gold; checks all answers are equal
  first. `reports/benchmark.md/.json`. Lesson: multi-year Parquet must be read with
  `union_by_name = true` (else the first file's columns are used and 2025-26-only columns vanish).
- `pipeline/build.py`: reads silver (`silver.tables_for_build()`); school-year table (enrolment by stage and sex, SC/ST/CWSN,
  facility flags, infra index, teachers, PTR, single-teacher, quality flags) and
  district summaries (girls' share, retention gap, progression ratios).
- `pipeline/checks.py`: automated QA report `reports/qa_report.md` (coverage,
  schema drift, undocumented codes, logical checks, validation vs official,
  district moves, year-on-year jumps).
- `download_udise.py` (Playwright downloader), `organise_downloads.py`.
- `DATA_QUALITY_LOG.md`: 22 documented findings and decisions. Keep it updated.
